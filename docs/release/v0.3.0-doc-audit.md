## Findings

### VERIFIED INDEPENDENTLY (direct code evidence, before workflow returns)
1. **[HIGH / release-gating] "estimated until you calibrate" overpromises — C3 runtime application did NOT ship.**
   `tokenwatt calibrate probe|campaign|fit` produce a per-(machine,model) profile JSON, but the live
   proxy never loads or applies it. Evidence: proxy.py has zero profile/calib refs; cost.py imports only
   EnergyByRail (cost = measured energy × FlatRate); ledger.py has no calib_* columns; profiles.py is
   imported nowhere outside calibration.py/cli.py. So calibrating does NOT change reported costs — the
   ledger still reads "estimated (±15–30%)". README lines 15, 44, 154 imply an estimated→calibrated flip
   the code can't deliver end-to-end. → DECISION NEEDED: implement C3 for v0.3.0, or reframe docs (calibration
   = measurement/correction artifact; auto-application deferred) + document deferred.
2. **[MED] README omits the `tokenwatt calibrate` command entirely** — the headline v0.3.0 feature is
   referenced 3× ("calibrate against a wall meter") but never documented (not in Use list, no section, no
   Shelly setup). Command group is real (cli.py:96–195: probe/campaign/fit). Pure coverage gap.
3. **TOU/time-of-use pricing is NOT implemented** — zero occurrences in src/; rate.py is only FlatRate.
   README does not claim TOU (good). Must confirm the design spec doesn't present TOU as shipped.
4. **C4 (interactive wizard + `calibrate show`) and C5 (per-rail fit) did not ship** — no `show` command;
   per-rail not in code. Any doc presenting them as available is an overpromise (design spec labels them
   as gated/future — likely OK, workflow confirming).
